# 簡易ブックマークの設定（iPhone・PC）

読みたい記事を 1 操作で Viewer に保存するための設定。保存した時点ではスライド等は作られない。
常駐プロセスが動いていれば、あとから 3 行要約とタイトルが付く（`INBOX_SUMMARY_ENABLED=true` のとき）。

| 入口 | しくみ | PC が止まっていても保存できるか |
|---|---|---|
| iPhone の共有メニュー | ショートカット → GitHub → 記事を登録 | できる |
| PC のブックマークバー | ボタン → Viewer の小窓 → 依頼キュー → 常駐プロセスが登録 | できない（常駐プロセスが必要） |

## 1. iPhone：共有メニューから 1 タップで保存する

### 1.1 GitHub のアクセストークンを作る（最初の 1 回）

1. GitHub の Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token。
2. Repository access は **Only select repositories** にし、`lomoxiao/article-to-slides-automation` だけを選ぶ。
3. Repository permissions は **Contents: Read and write** だけにする。ほかは付けない。
   - `repository_dispatch` を送るのに必要な権限。足りない場合、GitHub の応答ヘッダー
     `X-Accepted-GitHub-Permissions` に必要な権限が出るので、それに合わせる。
4. 有効期限を設定する（例: 90 日）。期限が切れると保存できなくなるので、切れる前に作り直す。
5. 表示されたトークンを控える（この画面でしか見られない）。

注意: このトークンはショートカットの中に保存される。漏れた場合に操作されるのはこのリポジトリだけだが、
内容の書き換えもできる権限なので、iPhone のショートカットを人に共有しないこと。不要になったら GitHub 側で削除する。

### 1.2 ショートカットを作る

iPhone の「ショートカット」アプリで、共有メニューから呼べるショートカットを 1 つ作る。所要 10 分ほど。
画面の文言は iOS の版によって少し違うことがある。下の説明と多少違っても、近い名前のものを選べばよい。

完成すると、次のブロックが上から並ぶ。

```
[共有シートから「URL」「Safari Webページ」を受け取る]
1. ショートカットの入力 から URL を取得
2. URL の内容を取得（GitHub に送る）
3. もし「URL の内容」に値がない（＝成功）
4.     通知を表示「Viewer に保存しました」
   そうでなければ
       通知を表示「保存に失敗しました：」＋ GitHub の応答
   終了
```

#### 手順 0：準備

- 1.1 で作ったトークン（`github_pat_` で始まる長い文字列）を iPhone のメモアプリ等にコピーしておく。
  手順 3 で貼り付ける。貼り付け終わったら、メモ側のトークンは削除する。

#### 手順 1：新しいショートカットを作り、共有メニューに出す

1. 「ショートカット」アプリを開き、画面下の「ショートカット」タブで右上の「＋」をタップする。
2. 画面上部の名前（「新規ショートカット」など）をタップ →「名称変更」で **Viewerに保存** にする。
3. 名前の横の「∨」（または画面下の ⓘ）をタップ →「詳細」（または「情報」）を開き、
   **「共有シートに表示」をオン**にして「完了」を押す。
4. 編集画面の一番上に「**[画像 と 18 項目] を共有シートから受け取る**」のような、青い文字を含むブロックが現れる。
   - 青い「画像 と 18 項目」の部分をタップし、いったん「すべて選択解除」してから、
     **「URL」と「Safari Webページ」の 2 つだけ**にチェックを入れる。
   - 同じブロックの「入力がない場合」は「停止」のままでよい。

#### 手順 2：共有されたページから URL を取り出す

1. 画面下の検索欄（「アクションを検索」）に **URL** と入力し、「**入力から URL を取得**」をタップして追加する。
2. 追加されたブロックが「**ショートカットの入力** から URL を取得」になっていることを確認する。
   （別の言葉になっていたら、その青い文字をタップして「ショートカットの入力」を選ぶ）

#### 手順 3：GitHub に送る

1. 検索欄に **URLの内容** と入力し、「**URL の内容を取得**」を追加する（手順 2 のブロックの下に付く）。
2. ブロックの中の青い「URL」の部分をタップする。候補の変数は選ばず、キーボードで次をそのまま入力する。

   ```
   https://api.github.com/repos/lomoxiao/article-to-slides-automation/dispatches
   ```

   ※ ここは送り先（GitHub）の住所。手順 2 で取り出した記事の URL を入れる場所ではない。
3. ブロックの下の「**表示を増やす**」（または「＞」）をタップして、詳しい設定を開く。
4. 「方法」をタップして **POST** を選ぶ。
5. 「ヘッダ」の「**新規ヘッダを追加**」を 2 回タップし、次の 2 つを入れる（左の欄がキー、右の欄が値）。

   | キー | 値 |
   |---|---|
   | `Authorization` | `Bearer ` に続けてトークンを貼り付けたもの |
   | `Accept` | `application/vnd.github+json` |

   - `Bearer` とトークンの間には**半角スペースを 1 つ**入れる。例：`Bearer github_pat_11ABC...`
   - 大文字・小文字も含めて、上の表のとおりに入れる。
6. 「本文を要求」をタップして **JSON** を選ぶ。
7. 「**新規フィールドを追加**」→「**テキスト**」を選び、次を入れる。
   - キー：`event_type`
   - テキスト：`register-article`
8. もう一度「新規フィールドを追加」→ 今度は「**辞書**」を選ぶ。
   - キー：`client_payload`
   - 値の欄（「0 項目」などと表示される所）をタップすると、辞書の中身を編集する画面が開く。
   - その画面で「新規フィールドを追加」→「テキスト」を 2 回行い、次の 2 つを入れる。

     | キー | テキスト |
     |---|---|
     | `url` | 手順 2 の「URL」（下の入れ方を参照） |
     | `from` | `shortcut` |

   - `url` のテキスト欄は、キーボードで打たない。テキスト欄をタップしたときにキーボードの上に出る
     **「変数を選択」**（または候補の並び）から、手順 2 で作った「**URL**」を選ぶ。
     欄に青い「URL」のかたまりが入れば正しい。
   - 入れ終わったら「完了」で辞書の画面を閉じる。

   ページのタイトルは送らなくてよい。保存した記事のタイトルは、あとで常駐プロセスが本文から付ける。

#### 手順 4：結果を通知する（失敗に気づけるようにする）

GitHub は、受け付けたときは**何も返さない**（空の応答）。失敗したときはエラーの文章を返す。
この違いを使って、成功と失敗で通知を分ける。

1. 検索欄に **もし** と入力し、「**もし**」を追加する。「もし」「そうでなければ」「終了」の 3 行が一度に入る。
2. ブロックが「もし **URL の内容** が …」になっていることを確認する
   （別の言葉になっていたら、青い文字をタップして「URL の内容」を選ぶ）。
3. 「条件」をタップし、「**値がない**」（または「任意の値がない」）を選ぶ。
4. 検索欄に **通知** と入力し、「**通知を表示**」を追加する。長押しで掴み、「もし」と「そうでなければ」の**間**に移す。
   文字を「**Viewer に保存しました**」にする。
5. もう 1 つ「通知を表示」を追加し、「そうでなければ」と「終了」の**間**に移す。
   文字を「保存に失敗しました：」にし、その後ろに変数「**URL の内容**」を入れる（失敗の理由が表示される）。
6. 右上の「完了」で保存する。

#### 手順 5：試す

1. Safari で適当な記事を開き、画面下の共有ボタン（四角から上向きの矢印）をタップする。
2. 共有メニューを下にスクロールし、「**Viewerに保存**」をタップする。
   - 共有メニューの上の方に出したい場合は、一番下の「アクションを編集」で「よく使う項目」に追加する。
3. 初回だけ「『api.github.com』への接続を許可しますか」と聞かれる。**「常に許可」**を選ぶ。
4. 「Viewer に保存しました」と通知が出れば成功。1〜2 分後に Viewer の一覧に出る。

Safari 以外（Chrome、X、YouTube アプリなど）でも、共有メニューに URL が含まれていれば同じように使える。

#### うまくいかないとき

| 症状 | よくある原因と直し方 |
|---|---|
| 共有メニューに「Viewerに保存」が出ない | 手順 1-3 の「共有シートに表示」がオフ。または手順 1-4 で「URL」「Safari Webページ」が選ばれていない |
| 「保存に失敗しました：Bad credentials」 | トークンの貼り間違い、`Bearer` の後の半角スペース抜け、トークンの期限切れ |
| 「保存に失敗しました：Not Found」 | 送り先の URL の打ち間違い、またはトークンの対象リポジトリ・権限（Contents）の設定違い |
| 「保存に失敗しました：」の後に `Invalid request` など | 本文の形の誤り。`event_type`・`client_payload`・`url` の綴りと、`client_payload` が「辞書」になっているかを確認する |
| 成功の通知が出たのに Viewer に出ない | GitHub のリポジトリの「Actions」タブで「Register Article」の実行結果を見る。赤い × なら、開いたログに理由が出ている |

#### トークンを作り直したとき（期限切れなど）

ショートカットを開き、「URL の内容を取得」の「ヘッダ」にある `Authorization` の値を、`Bearer ` ＋ 新しいトークンに書き換える。ほかは変えなくてよい。

## 2. PC：ブックマークバーのボタンで保存する

### 2.1 ボタンを作る（最初の 1 回）

ブラウザのブックマークバーに新しいブックマークを作り、名前を「Viewerに保存」、URL を次の 1 行にする。

```
javascript:(function(){window.open("https://lomoxiao.github.io/multimodal-article-viewer/?save="+encodeURIComponent(location.href)+"&title="+encodeURIComponent(document.title),"viewer-save","width=420,height=280");})();
```

### 2.2 使い方

保存したいページでボタンを押す。小さな窓が開き、「Viewer に保存しました」と出て自動で閉じる。

- 初回や、Viewer にサインインしていないときは、小窓にサインイン画面が出る。サインインすると保存が続く。
- 小窓が出ない場合は、ブラウザのポップアップブロックでこのサイトを許可する。
- 常駐プロセスが止まっていると、依頼は待ち行列に残り、次に起動したときに登録される。

## 3. 保存した記事はどこに出るか

Viewer の一覧に「未着手」の記事として出る（画面下のタブを入れたあとは「受信箱」）。
詳細から、あとでスライド・漫画・動画の生成や、束への追加ができる。

3 行要約を付けるには、常駐プロセスの `.env` に次を設定して再起動する。

```
INBOX_SUMMARY_ENABLED=true
```

- 保存した記事のうち、まだ何も生成しておらず、要約の無いものが対象。10 分ごとに最大 3 件ずつ処理する。
- 本文が取れないサイトの記事は、要約の代わりに「本文が取れていません（理由）」が出る。その記事は再試行しない。
